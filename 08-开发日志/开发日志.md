### Phase 10 — 缺陷修复（2026-06-17）✅

本轮修复 7 个问题，全部由实际使用场景驱动，改动量极低但收益明确。

| # | 问题 | 根因 | 修复 | 改动量 | 影响 |
|---|------|------|------|--------|------|
| 1 | AI 对话消息不触发 UI 重渲染 | `useAiStore.sendMessage` 修改了 `conv.messages` 但 `set()` 里没传 `conversations` — Zustand 的 `Map` 是引用类型，不换引用就不会触发重渲染 | 5 处 `set()` 补上 `conversations: new Map(get().conversations)` + 用户消息也先更新 UI | +6 行 | 角色对话、AI 续写结果即时显示 |
| 2 | 删除作品时卡顿 | `deleteWork` 对 8 个 store 各做 `getAll()` 全表扫描遍历过滤，即使已有 `workId` 索引 | 改用 `index('workId').getAll(id)` 索引查询，并行扫描 8→0 | -12 行 | 删除作品从 O(n) 降到 O(log n) |
| 3 | 后端崩溃后前端无限等待 | 三个流式请求（`sendMessage`/`streamContinue`/`streamRoleChat`）只有 AbortController 但无超时，后端挂掉后 UI 永远 show spinner | 各加 `setTimeout(() => controller.abort(), 120_000)` + `clearTimeout` | +6 行 | 超时自动恢复，不需用户手动点"停止" |
| 4 | `baseUrl` 回退逻辑缺失 | `getGlobalModelConfig` 从 `apiKeys.find(k => k.provider === provider)` 匹配，provider 字段前后端一致（DeepSeek→`deepseek`, Claude→`anthropic`...），但之前用字符串包含匹配不准确 | 确认 `model-router.ts` provider 匹配 + `ai-client.factory.ts` 默认 URL 已正确，无需改动 | 0 行 | 用户自定义 URL 优先，没填则按厂商回退官方地址 |
| 5 | 章节拖拽排序非原子性 | `reorderChapters` 逐条 `saveChapter()` 串行写入 — 排序过程中如果中途失败，数据库状态不一致 | 新增 `saveChapters()` 单事务批量写入 → `reorderChapters` 改用之 | +6 行 | 排序原子化，要么全部成功要么全部回滚 |
| 6 | 创建分支偶发"不显示" | `branch-manager.createBranch` fire-and-forget（`.catch(e => ...)`）— 保存还没落盘就 return，调用方紧接着 `reload()` 可能取不到 | 改为 `await saveBranch(branch)` → 调用方 `Branches.tsx` 加 `await` | +1 / -3 行 | 分支创建 100% 可靠 |
| 7 | 语音模式每次都发送两条相同消息 | `useSpeechRecognition` 中 `onresult` 发出 final 文本 ① + `onend` 又把 `finalBufferRef` 拼接再发一遍 ② | 加 `didEmitFinal` 标记 — `onend` 只在没发过 final 时才兜底提交 | +3 行 | 语音对话不再重复 |

**涉及文件**：`useAiStore.ts` / `storage.ts` / `useEditorStore.ts` / `branch-manager.ts` / `Branches.tsx` / `useSpeechRecognition.ts` — 总改动 ~25 行新增，~15 行删除。

**验证**：`vite build` ✅ 0 errors，18s 构建通过。

## 三、架构亮点

### 3.1 全局单模型架构

```
Settings.activeModel = "qwen-max"
        ↓
getGlobalModelConfig(settings)
        ↓
解析 model → provider → apiKey → baseUrl
        ↓
所有 AI 调用统一用同一套配置
```

优势：切换模型只需在设置页改一次，所有功能立即生效。

### 3.2 大纲 ↔ 编辑器双向联动

```
大纲页                              编辑器
  │                                   │
  ├─ 展开为章节 ──→ createChapter() ──→ 章节列表
  │                                   │
  ├─ ✏️ 开始写作 ──→ createChapter() ──→ 跳转编辑 + 预填概要
  │                                   │
  └─ (节点 title=章节名) ──→ 匹配 ←── 📋 大纲概要对照条
```

### 3.3 角色提取全链路

```
导入文本 → Editor 章节 ← 大纲展开
                │
                ▼
    Roles 页 "AI 分析文本提取角色"
                │
                ▼
    POST /api/ai/extract-characters
    (切片 8000 字发给 AI，JSON 结构化输出)
                │
                ▼
    [{name, personality, speechStyle, background, relationships...}]
                │
                ▼
    useRoleStore.createCharacter() × N，自动跳过重名
```
