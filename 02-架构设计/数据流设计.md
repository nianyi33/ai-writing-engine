# 数据流设计

## 核心数据流

### 1. AI 续写流程

```
用户在编辑器中定位光标
        │
        ▼
前端构建上下文包：
  - 前文(前800字) + 后文(后200字)
  - 当前章节大纲
  - 角色设定(当前场景相关角色)
  - 用户偏好(文风/人称等)
        │
        ▼
POST /api/ai/continue
  → 后端 AI Router 选择模型
  → 拼接 System Prompt + 上下文
  → 转发到 AI API (SSE 流式)
        │
        ▼
前端 SSE 接收 → AiStreamRenderer 实时显示
        │
        ▼
用户 "接受" → 插入到编辑器 → 触发版本快照
用户 "拒绝" → 丢弃生成文本
```

### 2. 版本历史机制

```
编辑器中每次 AI 修改前：
  1. 保存当前完整内容快照 → IndexedDB (versions store)
  2. 记录元数据：时间戳、触发原因、内容 hash
  3. 快照保留策略：最近10个完整 + 旧版本每5个保留1个（稀疏化），总上限50个
  4. 用户手动 Ctrl+S → 也触发快照（标记为手动版）

版本回退：
  1. 用户选择历史版本
  2. 展示 diff 对比
  3. 确认回退 → 当前内容替换为历史版本
  4. 回退前自动保存当前版本（不丢数据）
```

### 3. 存储金字塔

```
         ┌──────────────┐
         │  运行时内存    │  ← Zustand stores (当前会话)
         │  超快、丢失即毁 │
         ├──────────────┤
         │  IndexedDB   │  ← 持久化 (作品/章节/版本/角色)
         │  快、持久      │
         ├──────────────┤
         │  本地文件系统  │  ← File System Access API (导入/导出)
         │  慢、可共享    │
         ├──────────────┤
         │  后端代理     │  ← API Key 走 Express，不存前端
         │  安全边界     │
         └──────────────┘
```

## AI 对话上下文管理

```
单次续写请求的上下文拼接：

[System Prompt — 写作助手角色定义]        ← 固定，约 500 tokens
[用户偏好设定]                            ← 动态，约 200 tokens
[当前作品大纲摘要]                        ← 动态，约 300 tokens
[当前场景角色设定]                        ← 动态，约 200 tokens
[前文(最近 800 字)]                       ← 自动截取，约 600 tokens
[用户续写指令]                           ← 用户输入，约 50 tokens
─────────────────────────────────────────
总计约 1850 tokens → 远低于 64K 上限

对长上下文场景（分析全文/反向大纲）：
  → 分块处理：将全文分为 4000 字块
  → 逐块注入 + 块间摘要压缩
  → Token 预算实时显示在 UI
```
