# 分支结局功能设计

## 用户场景

你在飞卢/起点写了一本修仙小说，60 万字完结了。但是你对结局不满意——女主林霜死了，你觉得太虐。你想看看"如果林霜没死，和主角一起飞升"的版本。

上传整本小说 → 标记分叉点（第 58 章"林霜挡下致命一击"） → AI 从那个点重新出发 → 生成一个全新的结局分支。

你可以给分支起名："林霜存活线"，还有一个"黑化线"（如果主角选择复仇而不是原谅）。三个结局并存，随时切换。

---

## 核心概念：故事版本树

```
                    第1章 → 第2章 → ... → 第57章 → 第58章（分叉点）
                                                        │
                    ┌───────────────────────────────────┼───────────────────────────┐
                    ▼                                   ▼                           ▼
              【主线 canon】                      【分支 A：林霜存活】            【分支 B：黑化复仇】
         第59章 → 第60章（林霜死）              第59章'→ 第60章'（团圆）       第59章"→ 第60章"（复仇）
                    │                                   │                           │
              原版结局                              美好结局                     暗黑结局
```

- **每个分支都是独立的章节序列**，从分叉点开始各自发展
- **公共前文共享**（第1-57章所有分支通用）
- **分支间内容隔离**，互不影响
- **可以随时在分支间切换查看**

## 操作流程

### Step 1：导入现有小说

```
用户操作：拖入 / 选择 .md 文件，或从已有作品导入
    ↓
系统处理：
  - 解析章节结构（按 # 标题 或 --- 分隔符）
  - 识别章节标题和内容
  - 自动建立 chapter 列表
    ↓
导入完成 → 显示章节树
```

### Step 2：标记分叉点

```
用户在章节树中选择分叉点
    ↓
点"从这里创建分支" → 输入分支名称 + 结局方向描述
    │
    │  示例输入：
    │  分支名："林霜存活线"
    │  结局方向："希望林霜在挡下攻击后只是重伤，
    │             被送入秘境疗伤，主角在最终一战前
    │             与她重逢，两人合力击败最终boss，
    │             一起飞升。基调：温暖治愈，有情人终成眷属"
    │
    ▼
AI 分析现有内容（第58章之前的所有章节）
    ↓
AI 生成一个"幸福版"的后续大纲
```

### Step 3：AI 分析 + 生成

```
输入给 AI：
  1. 前文全文（第1-57章）→ 让 AI 理解人物、情节、世界观
  2. 分叉点上下文（第58章"挡下致命一击"的场景）
  3. 用户对结局的方向描述
  4. 原版结局（可选，让 AI 知道要"避开什么"）

AI 处理流程：
  Step A: 生成分支大纲（3-5 章的走向概要）
  Step B: 用户审核大纲，可手动调整
  Step C: 逐章生成正文（每章可单独重试）
    ↓
每章生成后 → 用户审阅 → 接受 / 调整后接受 / 重写
```

### Step 4：分支管理

```
分支列表：

  ┌──────────────────────────────────────────────┐
  │ 📖 主线 (canon)                               │
  │    第59章 绝境 · 第60章 终焉                   │
  │    字数: 8,200  创建: 2026-01-15               │
  │                                               │
  │ 🌸 林霜存活线                                  │
  │    第59章' 秘境疗伤 · 第60章' 重逢 · 第61章' 飞升│
  │    字数: 7,800  创建: 2026-06-08   ✅ 已完成    │
  │                                               │
  │ 🖤 黑化复仇线                                  │
  │    第59章" 入魔 · 第60章" 清算                 │
  │    字数: 3,200  创建: 2026-06-08   ✍️ 写作中    │
  │                                               │
  │ [+ 创建新分支]                                 │
  └──────────────────────────────────────────────┘
```

### Step 5：导出

```
导出选项：
  ○ 只导出当前分支（完整的第1-60章，含公共部分+分支独有）
  ○ 导出全部分支到一个文件（分章节标注各分支差异）
  ○ 导出分支对比文档（分叉点后，三栏并排显示差异）
```

## 数据模型

```typescript
// 新增：分支定义
interface StoryBranch {
  id: string;
  workId: string;
  name: string;               // 分支名称："林霜存活线"
  description: string;        // 用户描述的结局方向
  isCanon: boolean;           // 是否为主线（原版）
  divergeChapterId: string;   // 分叉点章节 ID
  divergePosition: number;    // 分叉点位置（该章节中的字符偏移量）
  status: 'planning' | 'writing' | 'done';
  createdAt: number;
  updatedAt: number;
}

// 分支章节：复用了 Chapter 结构，但新增 branchId 字段
interface BranchChapter {
  id: string;
  workId: string;
  branchId: string;           // ← 关联到哪个分支
  title: string;
  content: string;
  order: number;              // 分支内的排序（从分叉点后第1章开始）
  divergeFromChapterId: string; // 从这个章节开始分叉
  isAiGenerated: boolean;
  createdAt: number;
  updatedAt: number;
}

// 分支间的对应关系（用于对比视图）
interface BranchAlignment {
  canonChapterId: string;     // 主线章节
  branchChapterId: string;    // 对应分支章节
  similarity: number;         // 0-100，内容相似度
  keyDifferences: string[];   // 核心差异点列表
}
```

## Prompt 策略

### 分支大纲生成

```
你是一位小说走向策划师。用户对当前作品的结局不满意，希望你设计一个不同的结局。

## 已有作品信息（分叉点之前）
- 作品背景：{{workSummary}}
- 主要角色：{{characterSummaries}}
- 故事主线：{{mainPlot}}
- 分叉点事件：{{divergeEvent}}
- 分叉点位置：第{{divergeChapterNumber}}章

## 原版结局（供参考，请走向不同方向）
{{originalEnding}}

## 用户期望的结局方向
{{userDirection}}

## 任务
基于分叉点之前的公共内容，设计一个与用户期望方向一致的新结局。

## 输出格式（JSON）
{
  "branchName": "分支名称",
  "tone": "基调描述（温暖/虐心/爽文/...）",
  "outline": [
    {
      "chapterNumber": 59,
      "title": "章节标题",
      "summary": "300字内容概要",
      "keyEvents": ["事件1", "事件2"],
      "characterChanges": ["角色XX的变化"],
      "emotionCurve": "先抑后扬/持续上涨/..."
    }
  ],
  "totalChapters": 4,
  "estimatedWords": 12000,
  "satisfactionNote": "这个结局实现了用户想要的XX，同时保持了XX的连贯性"
}
```

### 分支章节续写

与续写助手 Prompt 相同，但注入的上下文切换为：
- 公共前文（分叉点之前的章节）
- 当前分支的已写章节
- 当前分支的大纲

## UI 组件

### 分支树视图（新增组件）

```
<BranchTree>
  ├── <BranchTimeline>        ← 横向时间线，显示分叉点
  │     ├── 公共路径（灰色）
  │     └── 各分支路径（不同颜色）
  │
  ├── <BranchSelector>        ← 下拉/标签切换当前查看的分支
  │
  └── <BranchComparison>      ← 分叉点后，并排显示各分支内容
        ├── 主线列
        ├── 分支 A 列
        └── 分支 B 列
```

## 实现优先级

| 功能 | 优先级 | 阶段 |
|------|--------|------|
| 导入整本小说 + 自动分章 | P1 | Phase 4 |

| 分支大纲 AI 生成 | P1 | Phase 3（复用 Prompt 工程） |
| 分支内章节续写 | P0 | Phase 3（复用续写助手） |
| 分支列表管理 | P1 | Phase 4 |
| 分支树可视化 | P2 | Phase 5 |
| 多分支并排对比 | P2 | Phase 5 |
| 分支导出（全量/单分支） | P2 | Phase 5 |
| 分支间 AI 差异分析 | P3 | 后续迭代 |
