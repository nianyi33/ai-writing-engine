# 技术选型方案

## 核心决策：纯 Web vs Tauri 2

### 方案 A：纯 Web + File System Access API

| 维度 | 评价 |
|------|------|
| 技术栈匹配 | ⭐⭐⭐⭐⭐ 与现有 React/Vite/Express 完全一致 |
| 开发速度 | ⭐⭐⭐⭐⭐ 无新语言/框架学习成本 |
| 本地文件访问 | ⭐⭐⭐ File System Access API (Chrome/Edge 支持良好) |
| 桌面体验 | ⭐⭐⭐ PWA 可实现离线、快捷方式 |
| 移动端访问 | ⭐⭐⭐⭐ 天然支持（响应式 Web） |
| 打包分发 | ⭐⭐⭐ 需 Electron 或直接用浏览器 |
| 文件系统深度 | ⭐⭐ 无法遍历目录、批量操作受限 |

### 方案 B：Tauri 2 桌面壳

| 维度 | 评价 |
|------|------|
| 技术栈匹配 | ⭐⭐ 需引入 Rust + Tauri CLI |
| 开发速度 | ⭐⭐ Rust 学习曲线 + 编译等待 |
| 本地文件访问 | ⭐⭐⭐⭐⭐ 完整文件系统权限 |
| 桌面体验 | ⭐⭐⭐⭐⭐ 原生窗口、托盘、快捷键 |
| 安装包大小 | ⭐⭐⭐⭐⭐ ~5MB（vs Electron ~120MB） |
| 团队能力匹配 | ⭐ 当前团队纯 Node/Web 栈 |

### 最终推荐：方案 A（纯 Web + PWA）+ 未来可迁移 Tauri 2

**理由**：
1. 现有"AI赋能引擎"全部代码可直接复用，零迁移成本
2. File System Access API 对写作应用足够（读写单个文件/目录）
3. MVP 验证阶段不应被 Rust 学习曲线拖慢
4. **PWA 让 Web 应用像桌面软件一样打开**（独立窗口、桌面图标、离线可用）
5. 如果产品验证成功，后续用 Tauri 2 包裹只需新增 Rust 桥接层，前端代码完全不变

**双阶段策略**：

```
Phase 2-4 (MVP)           Phase 5+ (正式发布)
───────────────           ──────────────────
  纯 Web + PWA     →      Tauri 2 桌面壳
  浏览器安装              .exe / .dmg 安装
  体验可达 80%            体验达到 100%
  开发成本: 0             开发成本: +3-5 天
```

> 详见 [PWA配置与Tauri迁移路径](PWA配置与Tauri迁移路径.md)

## 技术栈明细

| 层 | 技术 | 说明 |
|----|------|------|
| 框架 | React 19 + TypeScript 5.8 | 与现有一致 |
| 构建 | Vite 7 | 与现有一致 |
| 样式 | Tailwind CSS 3 + Ant Design 6 | AntD 用于管理面板组件 |
| 编辑器 | CodeMirror 6 (@codemirror/*) | Markdown 编辑 + 语法高亮 |
| Markdown 渲染 | react-markdown + remark-gfm | 预览面板 |
| 路由 | react-router-dom 7 | SPA 路由 |
| 状态管理 | Zustand 5 | 轻量、无 boilerplate |
| 图表 | ECharts + echarts-for-react | 大纲评分雷达图 |
| 本地存储 | IndexedDB (idb) | 文件 + 版本历史 |
| 文件系统 | File System Access API | 导入/导出本地文件 |
| AI 客户端 | OpenAI SDK (DeepSeek 兼容) | 多模型统一接口 |
| 流式 | SSE (EventSource + fetch stream) | AI 实时输出 |
| 后端 | Express 4 + TypeScript | API 代理 + 本地文件服务 |
| PWA | vite-plugin-pwa + workbox | 离线缓存 + 桌面安装 |
| 测试 | Vitest + Testing Library | 单元 + 组件测试 |

---

## 不引入的新技术（MVP 阶段）

- ❌ Electron（太重，120MB+ 安装包）
- ❌ Tauri 2（MVP 阶段学习成本高，Phase 5+ 再引入）
- ❌ 新数据库（继续用 IndexedDB，未来可加 SQLite via OPFS）
- ❌ 新框架（不引入 Next.js/Remix，保持 SPA 模式）

## PWA 桌面化配置

| 依赖 | 用途 |
|------|------|
| `vite-plugin-pwa` | Vite 构建时注入 Service Worker + manifest |
| `workbox-precaching` | 静态资源预缓存（离线可用） |
| `workbox-routing` | API 请求 NetworkFirst 策略 |
| `manifest.json` | 桌面安装配置（图标、名称、独立窗口模式） |

> 完整配置见 [PWA配置与Tauri迁移路径](PWA配置与Tauri迁移路径.md)
