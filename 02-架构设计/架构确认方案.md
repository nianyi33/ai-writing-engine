## 一、架构决策终审

### 决策 1：项目位置与 Phase 编号

```
决策：在现有 code/ 下创建 phase-5-writing/

d:/AI赋能引擎/code/
├── shared/                   ← 共享代码（复用）
├── phase-1-mvp/              ← 游戏生成
├── phase-2-streaming/        ← 流式
├── phase-3-multimodal/       ← 工作流
├── phase-4-community/        ← 社区
├── phase-5-writing/          ← 🆕 AI写作引擎（本Phase）
└── backend/                  ← Express 后端（复用扩展）
```

**理由**：
- 与现有项目统一管理，共享 `shared/` 模块零路径改动
- 共享代码修改时，所有 Phase 自动受益
- `@shared` 别名无需重配

### 决策 2：IndexedDB 独立数据库

```
决策：新建 ai-writing-engine 数据库，不复用 ai-game-studio
```

**理由**：
- 写作数据（章节/版本/角色/大纲）与游戏数据（HTML/精灵图/音效）维度完全不同
- 独立数据库避免 Schema 互相污染
- 未来可独立备份/迁移写作数据

### 决策 3：PWA 内置，Tauri 后置

```
Phase 2: 内置 vite-plugin-pwa → 浏览器安装就能用
Phase 5: 加 src-tauri/ → npx tauri build → .exe / .dmg
```

前端代码改动量：Phase 2 时 0（纯粹的 vite 插件配置），Phase 5 时 < 200 行（File System Access API → Tauri fs plugin）。

### 决策 4：DeepSeek 默认 + Claude 高价值场景

```
日常续写 → DeepSeek-Chat（快、便宜、中文好）
大纲分析 → Claude-Sonnet（推理强、结构化输出稳）
角色对话 → Claude-Sonnet（角色扮演更自然）
```

保留多模型切换能力，用户可自行绑定。

### 决策 5：文件导入范围

```
MVP (Phase 2)：仅 .md 文件
  - 解析器：按 # 标题层级拆分为章节
  - fallback：按 --- 分隔符拆分
  - 纯 txt 文件按 3 次以上空行拆分

Phase 5+：.epub 导入
  - 需 epub.js 或后端解压解析
```

  scenario: 'continue';
  systemPrompt: string;      // 拼接好的完整 System Prompt（含上下文）

## 四、风险架构缓解

### 风险1：AI输出不稳定

```
缓解架构：
  1. 重试队列（最多3次，指数退避）
  2. 输出校验层（JSON parse → schema validate → fallback retry）
  3. Temperature 锁定（关键场景锁死在 0.3-0.5）
  4. 降级兜底：AI异常时展示"请重试" + 手动输入区域
```

### 风险2：长文本上下文超限

```
缓解架构：
  1. 分层上下文注入：
     L1（必注）: System Prompt + 用户指令 + 前800字
     L2（预算允许）: 当前章节大纲 + 出场角色
     L3（预算宽松）: 全书摘要 + 历史关键事件
  2. Token 预算实时计算 → UI 展示余量
  3. 超限时自动降级：砍 L3 → 砍 L2 部分
```

### 风险3：分支结局的上下文一致性

```
缓解架构：
  1. 公共前文（分叉点之前）→ 只读锁定，不可修改
  2. 分支内容 → 独立存储，写入时注入"分叉点上下文摘要"
  3. 角色状态快照 → 分叉点处保存所有角色的当前状态
  4. AI 续写时注入："这是第XX章，分叉点是第XX章，
     自那以后的变化是：XXX。公共历史上不变的设定是：XXX"
```
